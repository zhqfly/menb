## 使用约定

1. 按自己的岗位标题阅读；跨岗位事项以文末协作表划界。
2. 做完一轮工作，按「产出回写对照」更新领域页，不要只改本页条文。
3. 修订岗位职责时直接改本 Markdown，并在 [决策记录](./06-决策记录.md) 留痕。
4. 每个阶段保持四段：步骤、核心工作、输出物、关键提示，便于对照和评审。

## PMO（项目管理办公室）

组织级项目管理中枢：体系建设、组合管理、流程治理、资源统筹、知识沉淀。确保项目朝着战略目标推进。

### 1. 立项与准入

> 项目入口管控 · 战略对齐评估 · 资源可行性分析

**步骤：** 需求提出 → 材料审核 → 立项评审 → 登记入册 → 分配PM

**核心工作**

- **接收申请：** 接收项目申请，审核立项材料完整性（商业论证、可行性分析、预估资源、预期收益）
- **战略对齐评估：** 评估项目与组织战略的对齐度，分析必要性和优先级
- **资源可行性分析：** 评估人力、资金、设备是否可获取，识别资源冲突
- **组织立项评审：** 组织立项评审会，做出立项 / 暂缓 / 驳回决策
- **项目登记入册：** 编号登记，纳入组合看板，明确项目级别和治理要求
- **分配项目经理：** 按级别、复杂度、技术栈匹配项目经理
- **发布项目章程：** 正式宣布启动，授权项目经理动用组织资源

**输出物：** 立项决议 · 项目编号 · 项目章程 · 组合看板更新

**关键提示：** 立项是治理第一关，要审商业论证，避免拍脑袋立项。资源评估实事求是，不要为了立项低估需求。

### 2. 规划与启动

> 计划编制指导 · 基线审核 · 治理结构搭建 · 沟通机制建立

**步骤：** 启动会 → 计划编制 → 计划评审 → 基线锁定 → 沟通机制

**核心工作**

- **指导计划编制：** 指导项目经理用组织标准模板编制项目管理计划
- **审核计划合理性：** 审关键路径、资源负载、预算、风险应对、质量标准
- **组织计划评审：** 邀请管理层和关键干系人评审
- **锁定项目基线：** 锁定范围、进度、成本三重基线，作为后续监控基准
- **建立治理结构：** 明确汇报关系、决策机制、升级路径、评审节点
- **建立沟通机制：** 确定报告频率、会议机制、信息分发方式
- **配置项目管理工具：** 配置 Jira / 禅道 / MS Project 等，建立项目空间和权限

**输出物：** 项目管理计划 · 三重基线 · 治理结构文件 · 沟通计划

**关键提示：** 计划评审看「能不能执行」，不是只看格式。基线锁定后变更必须走正式流程。

### 3. 执行与监控

> 状态跟踪 · 绩效分析 · 偏差预警 · 资源协调 · 阶段评审

**步骤：** 状态收集 → 绩效分析 → 偏差识别 → 预警触发 → 纠正措施

**核心工作**

- **状态收集：** 定期收集进度、成本、质量、风险、问题
- **绩效分析：** 对比基线，计算 SV、CV、SPI、CPI
- **偏差识别：** 识别超阈值偏差，分析原因和对目标的影响
- **预警机制：** 红黄绿灯预警，要求项目经理制定纠正措施
- **资源协调：** 监控组织级资源负载，调解跨项目冲突
- **阶段评审：** 组织 Gate Review，评估阶段交付物，决定是否进入下一阶段
- **组合报告：** 编制组合周报 / 月报
- **流程合规审计：** 审计项目是否按组织规范管理

**输出物：** 项目周报 · 组合月报 · 绩效报告 · 阶段评审纪要 · 预警通知 · 审计报告

**关键提示：** PMO 监控是支持性的，目的是帮项目成功。数据要真实，不要报喜不报忧。

### 4. 变更与风险控制

> 变更管控 · 风险应对 · 问题升级 · 跨项目协调

**步骤：** 变更/风险提出 → 影响评估 → CCB评审 → 决策执行 → 基线更新

**核心工作**

- **变更控制：** 初审变更完整性与必要性；评估范围、进度、成本、质量、风险影响；召集 CCB 批准 / 驳回 / 暂缓；批准后监督基线更新并通知干系人
- **风险管理：** 维护组织级风险登记册和应对知识库；推动各项目识别、评估、应对、监控；升级超出项目级能力的高风险；定期复盘积累案例
- **问题升级管理：** 项目级无法解决的跨部门阻塞由 PMO 协调并跟踪闭环
- **跨项目协调：** 识别依赖和资源冲突，组织跨项目协调会
- **重大问题决策支持：** 对暂停、终止、重大调整组织专项评估，向管理层提出建议

**输出物：** 变更请求单 · CCB决议 · 更新基线 · 风险登记册 · 问题跟踪表 · 专项评估报告

**关键提示：** 变更控制是管理变更，不是阻止变更。风险要早识别、早应对，不要等变成问题。

### 5. 收尾与复盘

> 验收监督 · 收益跟踪 · 知识沉淀 · 流程改进 · 组织能力提升

**步骤：** 验收监督 → 财务结算 → 资源释放 → 复盘总结 → 知识归档

**核心工作**

- **验收监督：** 确认验收标准和流程合规，材料完整，签署验收报告
- **财务结算审核：** 核对实际成本与预算差异并分析原因
- **资源释放确认：** 人员归队、设备归还、预算结转，更新资源池
- **组织项目复盘：** 引导总结成败；重大或失败项目做专项复盘；编制复盘报告
- **知识沉淀：** 归档文档、模板、交付物、复盘成果；更新组织过程资产
- **收益跟踪：** 项目后评价（PIR），跟踪实际收益和投资回报
- **流程持续改进：** 基于复盘和审计优化流程、工具、模板
- **项目经理能力评价：** 提供执行数据和评价建议

**输出物：** 验收报告 · 财务结算单 · 复盘报告 · 知识库条目 · 项目关闭通知 · 后评价报告 · 流程改进方案

**关键提示：** 复盘聚焦改进而非追责。知识沉淀要及时、可检索，不要只留在个人头脑里。

## 项目经理（Project Manager）

项目整体负责人，对范围、进度、成本、质量、风险和团队负总责，是项目成功的第一责任人。关键词：全周期负责、资源协调、风险管控、干系人管理、目标达成。

### 1. 项目启动与接手

> 明确目标 · 组建团队 · 建立治理 · 对齐期望

**步骤：** 接手项目 → 需求确认 → 组建团队 → 启动会

**核心工作**

- **接手项目：** 阅读章程、合同、立项材料，明确目标、范围边界、约束和成功标准
- **干系人识别：** 梳理客户、管理层、团队、供应商，分析期望、影响力和沟通策略
- **需求确认：** 与客户 / 产品方确认核心需求，识别模糊点和争议
- **组建团队：** 协调开发、测试、实施、设计等角色，明确分工
- **项目启动会：** Kick-off，对齐目标、范围、计划、沟通机制和团队规则

**输出物：** 干系人登记册 · 团队组建方案 · 启动会纪要 · 需求确认记录

**关键提示：** 务必对齐「项目成功的标准」。启动会上明确职责和汇报关系。

### 2. 项目规划与计划

> WBS分解 · 进度编排 · 资源预算 · 风险预案

**步骤：** 范围分解 → 进度计划 → 资源预算 → 风险计划 → 计划评审

**核心工作**

- **范围管理：** 组织 WBS，分解为工作包，明确负责人和交付物
- **进度计划：** 识别依赖，估算工期，编排关键路径，设置里程碑
- **资源与预算：** 编制人力、设备、资金需求和项目预算
- **风险管理：** 组织识别会，评估概率和影响，制定规避 / 转移 / 减轻 / 接受策略
- **质量管理：** 制定质量标准和验收准则
- **沟通计划：** 确定报告频率、会议机制、信息分发方式
- **计划评审：** 邀请管理层和关键干系人评审后锁定基准计划

**输出物：** 项目管理计划 · WBS · 进度计划（甘特图） · 预算表 · 风险登记册 · 沟通计划

**关键提示：** 计划颗粒度要匹配项目，建议留 10–15% 缓冲。风险应对要具体到责任人和行动步骤。

### 3. 项目执行与协调

> 任务派发 · 团队管理 · 沟通协调 · 问题解决

**步骤：** 任务分配 → 团队激励 → 沟通协调 → 问题解决 → 状态汇报

**核心工作**

- **任务派发：** 明确目标、交付标准、截止时间和验收方式
- **团队管理：** 每日站会 15 分钟，识别阻塞；关注士气和冲突
- **沟通协调：** 周例会、阶段评审，同步客户、管理层、团队；协调跨团队依赖
- **问题管理：** 建立问题日志；超出项目权限的问题及时升级
- **变更管理：** 评估对范围、进度、成本、质量的影响，提交 CCB，批准后更新计划
- **状态汇报：** 周报 / 月报，保证进度、成本、质量、风险、问题透明
- **质量管理：** 组织阶段交付物评审，推动测试和缺陷修复

**输出物：** 会议纪要 · 项目周报 · 问题日志 · 变更请求 · 状态报告

**关键提示：** 执行阶段的核心是协调和推动，不要陷入技术细节。需求变更必须走变更流程。

### 4. 项目监控与纠偏

> 绩效测量 · 偏差分析 · 预警触发 · 纠正措施

**步骤：** 数据采集 → 绩效分析 → 偏差识别 → 预警升级 → 纠偏跟踪

**核心工作**

- **进度监控：** 对比计划，计算 SV、SPI，识别延期风险
- **成本监控：** 对比预算，计算 CV、CPI
- **质量监控：** 跟踪缺陷密度、测试通过率、评审结果
- **风险监控：** 回顾风险登记册，识别新风险，评估应对有效性
- **偏差分析：** 对进度、成本、质量偏差做根因分析
- **预警机制：** 超阈值红黄绿灯预警，必要时升级管理层
- **纠正措施：** 赶工、快速跟进、资源调整、范围协商，并跟踪闭环
- **阶段评审：** 里程碑结束时组织 Gate Review

**输出物：** 绩效报告 · 偏差分析报告 · 预警通知 · 纠正措施计划 · 阶段评审纪要

**关键提示：** 监控是为了早发现、早解决，用数据说话。纠正措施要有责任人和完成时间。

### 5. 项目收尾与复盘

> 验收交付 · 结算释放 · 复盘总结 · 知识沉淀

**步骤：** 验收准备 → 交付验收 → 结算释放 → 复盘总结 → 知识归档

**核心工作**

- **验收准备：** 整理交付物清单和验收材料，确认标准和流程
- **交付验收：** 组织客户验收，确认符合合同和需求，签署验收报告
- **财务结算：** 核对实际成本、收入确认和回款
- **资源释放：** 人员归队、设备归还，确认供应商付款完成
- **项目复盘：** Retrospective，总结成败和改进机会
- **知识沉淀：** 将文档、模板、经验归档到本知识库
- **团队评价：** 反馈、发展建议、表彰
- **项目关闭：** 发布关闭通知，完成 PIR，跟踪收益

**输出物：** 验收报告 · 财务结算单 · 复盘报告 · 知识库条目 · 项目关闭通知 · 后评价报告

**关键提示：** 复盘对事不对人。知识沉淀要及时，不要项目结束很久才补文档。

## 实施人员（Implementation Engineer）

负责现场部署、配置、培训和上线交付，是产品到客户生产环境的桥梁。关键词：现场部署、系统配置、用户培训、数据迁移、上线交付。

### 1. 实施准备与调研

> 需求调研 · 环境确认 · 方案编制 · 计划制定

**步骤：** 需求调研 → 环境确认 → 方案编制 → 计划确认

**核心工作**

- **需求调研：** 了解业务流程、组织架构、用户角色、现有系统和数据
- **差异分析：** 对比标准功能与实际需求（标准满足 / 配置实现 / 定制开发 / 无法满足）
- **环境确认：** 确认操作系统、数据库、中间件、网络、硬件、证书、安全策略
- **数据调研：** 了解数据格式、量、质量，制定清洗和迁移方案
- **实施方案编制：** 部署架构、配置清单、迁移、培训、上线、回退、风险预案
- **实施计划：** 明确任务、责任人、时间节点，与客户和项目经理确认
- **进场准备：** 安装包、license、配置模板、培训材料、检查清单

**输出物：** 需求调研报告 · 差异分析报告 · 环境确认单 · 实施方案 · 实施计划

**关键提示：** 多问「为什么」，理解真实业务，不要只记表面功能。环境要亲自验证，不要只听「没问题」。

### 2. 环境部署与配置

> 系统安装 · 环境配置 · 数据初始化 · 功能验证

**步骤：** 环境检查 → 系统部署 → 参数配置 → 数据初始化 → 功能验证

**核心工作**

- **环境检查：** 核对 OS、CPU / 内存 / 磁盘、网络、端口、数据库 / 中间件
- **系统部署：** 按手册安装应用，配置 Web / 应用服务器、负载均衡，确认服务启动
- **数据库配置：** 创建实例、表空间、用户，执行初始化脚本，设置备份
- **系统参数配置：** 组织架构、角色权限、流程、编码规则、单据模板、消息通知
- **数据初始化：** 导入基础数据，清洗转换，验证完整性和准确性
- **接口配置：** 与 OA / ERP / 钉钉 / 企业微信等联调
- **功能验证：** 按用例验证核心功能，跟踪问题修复
- **部署文档：** 记录过程、参数、拓扑，形成运维手册

**输出物：** 部署文档 · 配置清单 · 环境检查表 · 功能验证报告 · 运维手册

**关键提示：** 每一步都记录，配置变更先备份。数据导入先在测试环境验证。

### 3. 用户培训与指导

> 培训准备 · 分层培训 · 操作指导 · 效果考核

**步骤：** 培训计划 → 材料准备 → 分层培训 → 实操指导 → 效果确认

**核心工作**

- **培训计划：** 按角色和人数确定对象、时间、地点、方式和内容
- **培训材料：** PPT、操作手册、视频、练习题、测试账号，贴合客户业务
- **分层培训：** 管理层看价值、流程、报表；关键用户看操作、配置、内部支持；最终用户看日常操作
- **实操演练：** 在测试环境练习并现场答疑
- **培训考核：** 笔试 / 实操，未通过补训
- **培训记录：** 签到、内容、反馈、考核结果
- **建立支持渠道：** 问题群 / 热线，培养关键用户做内部支持

**输出物：** 培训计划 · 培训PPT · 操作手册 · 培训签到表 · 培训考核记录 · 培训报告

**关键提示：** 用客户的语言讲客户的业务。重点培养关键用户，培训后留足练习时间。

### 4. 试运行与问题处理

> 试运行支持 · 问题收集 · 缺陷修复 · 优化调整

**步骤：** 试运行启动 → 现场支持 → 问题收集 → 修复跟踪 → 优化调整

**核心工作**

- **试运行启动：** 明确范围、时间、人员、目标和反馈机制
- **现场支持：** 驻场答疑，指导正确使用
- **问题收集：** 台账分类为操作问题 / 配置问题 / 系统缺陷 / 需求变更
- **问题处理：** 操作问题现场指导；配置问题调整验证；缺陷提单给开发并回归；需求变更走变更流程
- **数据核对：** 核对系统数据与实际业务数据
- **性能监控：** 响应时间、并发、资源占用
- **优化调整：** 按反馈优化配置、流程和手册
- **试运行总结：** 评估是否具备正式上线条件

**输出物：** 问题台账 · bug清单 · 配置变更记录 · 试运行总结报告 · 上线评估报告

**关键提示：** 先解决影响业务的关键问题。所有问题入账，禁止口头处理。修复后必须回归。

### 5. 上线交付与验收

> 上线准备 · 正式切换 · 上线护航 · 验收移交

**步骤：** 上线检查 → 数据迁移 → 正式切换 → 上线护航 → 验收移交

**核心工作**

- **上线检查：** 功能、数据、培训、环境、备份、回退、应急预案
- **上线计划：** 时间、分工、步骤、验证点、回退条件，客户确认
- **数据迁移：** 在上线窗口清洗、转换、导入并验证
- **系统切换：** 启动生产服务，切换 DNS / 负载均衡
- **上线验证：** 冒烟测试核心流程
- **上线护航：** 通常 1–2 周驻场或远程支持
- **验收交付：** 演示功能，确认交付物，签署验收报告
- **文档移交：** 部署、运维、用户、配置、接口、培训材料
- **运维交接：** 账号、监控、备份、常见问题
- **实施总结：** 回顾过程，提出后续优化建议

**输出物：** 上线计划 · 上线检查清单 · 数据迁移报告 · 验收报告 · 文档移交清单 · 实施总结报告

**关键提示：** 必须有回退方案，窗口选业务低峰。验收前关闭关键问题。

## 开发人员（Developer）

负责设计、编码、测试和维护，对代码质量、功能实现和系统稳定性负责。关键词：需求分析、技术设计、编码实现、单元测试、缺陷修复。

### 1. 需求分析与方案设计

> 需求理解 · 技术方案 · 接口定义 · 工作量评估

**步骤：** 需求评审 → 技术调研 → 方案设计 → 接口定义 → 工作量评估

**核心工作**

- **需求理解：** 阅读需求 / 用户故事，参加评审，理解背景、场景和验收标准
- **需求澄清：** 对模糊、矛盾、技术不可行点主动确认
- **技术调研：** 验证新技术、框架、第三方 API 的可行性和风险
- **技术方案设计：** 模块与技术选型；表结构与约束；API（URL、方法、参数、错误码）；核心流程与状态机
- **方案评审：** 邀请团队和技术负责人评审可扩展性与风险
- **工作量评估：** 分解开发、联调、测试和 buffer，输出到项目计划
- **技术文档：** 编写设计、库表、接口文档

**输出物：** 技术设计文档 · 数据库设计 · 接口文档 · 流程图 · 工作量评估

**关键提示：** 问清楚再动手。方案要可维护，表结构上线后改动成本很高。

### 2. 开发准备与环境搭建

> 环境搭建 · 代码拉取 · 分支创建 · 规范确认

**步骤：** 环境搭建 → 代码拉取 → 分支创建 → 依赖配置 → 规范确认

**核心工作**

- **开发环境搭建：** 运行时、IDE、数据库、中间件、版本控制与项目要求一致
- **代码拉取：** 克隆仓库，确认版本和分支策略
- **分支创建：** 按规范创建 `feature/xxx`、`bugfix/xxx`，明确合并策略
- **依赖配置：** Maven / Gradle / npm / pip，保证本地可编译启动
- **数据库初始化：** 本地建库、脚本和连接
- **配置管理：** 区分开发 / 测试 / 生产，不提交密钥和密码
- **开发规范确认：** 命名、风格、注释、目录、commit 格式、review 流程
- **任务拆分：** 拆成可验收的子任务，建立个人清单

**输出物：** 本地开发环境 · 开发分支 · 可运行的项目 · 个人任务清单

**关键提示：** 环境与团队一致，禁止在主分支直接开发，敏感配置不入库。

### 3. 编码实现与单元测试

> 功能开发 · 代码自检 · 单元测试 · 接口联调

**步骤：** 模块开发 → 代码自检 → 单元测试 → 接口联调 → 功能自测

**核心工作**

- **功能开发：** 按设计与需求编码，保持清晰、可维护、可扩展
- **分层开发：** 后端实体 / DAO / Service / Controller；前端组件、路由、状态、API、校验；库表、索引、视图
- **代码自检：** 逻辑、边界、异常、规范、潜在缺陷
- **单元测试：** 覆盖核心逻辑、边界和异常
- **接口联调：** 对齐参数、格式和错误处理
- **功能自测：** 按验收标准在本地完整验证
- **性能考虑：** SQL、N+1、缓存、耗时异步
- **安全考虑：** 输入校验、注入、XSS、权限、敏感数据
- **代码注释：** 复杂逻辑、关键算法、公共接口

**输出物：** 功能代码 · 单元测试 · 接口联调记录 · 自测报告 · 代码注释

**关键提示：** 不要省略单测和自测。提交前自己先跑一遍，不要把明显缺陷留给测试。

### 4. 代码提交与测试修复

> 代码提交 · Code Review · 缺陷修复 · 回归验证

**步骤：** 代码提交 → Code Review → 合并代码 → 缺陷修复 → 回归验证

**核心工作**

- **代码提交：** commit 写清类型、简述、关联需求 / bug，按功能拆分提交
- **提交前检查：** 编译通过、单测通过、无调试代码、无敏感信息
- **创建合并请求：** 说明变更、影响范围、测试情况，指定 reviewer
- **Code Review：** 作者回应意见；评审关注正确性、质量、性能、安全、规范
- **代码合并：** 解决冲突，合并后走 CI/CD 到测试环境
- **缺陷修复：** 复现、找根因、修复且不引入新问题；严重缺陷优先
- **回归验证：** 确认原问题关闭且相关功能未坏
- **性能优化：** 按测试和监控结果优化
- **文档更新：** 接口、配置、部署变化同步文档

**输出物：** 合并请求 · Code Review记录 · bug修复代码 · 回归测试记录 · 更新的文档

**关键提示：** Review 不是走形式。修缺陷找根因。冲突仔细解，不要覆盖他人代码。

### 5. 发布上线与版本维护

> 发布准备 · 上线支持 · 问题排查 · 版本迭代

**步骤：** 发布准备 → 上线支持 → 问题排查 → 热修复 → 版本维护

**核心工作**

- **发布准备：** 确认功能清单、缺陷修复、配置和库变更；写 Release Notes；准备升级脚本和回退方案；参与发布评审
- **上线支持：** 配合发布，冒烟核心功能，看日志和告警，保持在线支持
- **问题排查：** 先定位类型（代码 / 配置 / 数据 / 环境 / 性能），先恢复业务再查根因
- **热修复：** 按紧急流程修复、验证、发布，随后合入主分支
- **版本维护：** 处理后续问题和优化，偿还技术债务，为下一迭代提供建议
- **知识沉淀：** 记录难点、方案、规范、常见问题

**输出物：** 发布说明 · 升级脚本 · 回退方案 · 问题分析报告 · 热修复版本 · 技术分享文档

**关键提示：** 生产变更必须有备份和回退。热修复后合入主分支。持续处理技术债务。

## 四岗位协作关系与职责边界

```text
PMO（治理统筹） ⇄ 项目经理（项目负责） ⇄ 实施人员（交付落地） ⇄ 开发人员（技术实现）
```

| 协作场景 | PMO | 项目经理 | 实施人员 | 开发人员 |
| --- | --- | --- | --- | --- |
| 需求阶段 | 审核需求完整性，评估战略对齐，管理组织级需求池 | 组织需求评审，管理需求范围，协调干系人 | 参与需求调研，提供业务视角和实施可行性建议 | 参与需求评审，评估技术可行性，提出技术建议 |
| 计划阶段 | 审核项目计划合理性，锁定项目基线，配置管理工具 | 制定项目计划，分配任务，排定进度 | 编制实施计划，评估实施工作量和风险 | 评估开发工作量，提供技术排期建议 |
| 开发阶段 | 监控开发进度和质量，审计流程合规，协调跨项目资源 | 跟踪开发进度，协调资源，处理阻塞问题 | 准备测试环境和测试数据，配合功能验证 | 按计划编码开发，自测，提交代码，修复缺陷 |
| 实施阶段 | 监督实施过程，管理实施风险，协调组织级资源支持 | 协调实施资源，管理客户期望，处理实施风险 | 现场部署、配置、培训、试运行支持 | 支持实施中的技术问题，修复现场发现的缺陷 |
| 问题处理 | 建立升级路径，协调跨部门问题，跟踪组织级问题闭环 | 问题升级协调，跟踪问题闭环，评估影响 | 收集现场问题，初步分类，协调修复验证 | 分析和修复技术问题，提供技术方案 |
| 变更管理 | 组织 CCB 评审，审批基线变更，监督变更执行 | 提交变更申请，评估变更影响，执行批准的变更 | 评估变更对实施的影响，配合变更实施 | 评估变更技术可行性，实施变更开发 |
| 上线验收 | 监督上线和验收流程合规，确认交付物完整 | 组织上线和验收，管理交付物，签署验收 | 执行上线操作，现场护航，办理文档移交 | 上线技术支持，处理上线技术问题 |
| 收尾复盘 | 组织复盘，沉淀组织过程资产，优化流程规范 | 组织项目复盘，总结项目管理经验 | 总结实施经验，完善实施方法论 | 总结技术经验，沉淀技术方案和最佳实践 |
